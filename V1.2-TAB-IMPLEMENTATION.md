# MATCHLATCH V1.2 — Five-Tab Functional Work Plan
October 9, 2026 · Development branch only

## MOOD — discover and start
Current: personal style-derived suggestions, saved archive shortcut, buttons to Studio and Store.
V1.2: meaningful source context when starting a look, exact category handoff to Store, clear indication that mood is inspiration (not inventory).
Acceptance: a MOOD direction sends its query and clothing category to STORE; selecting Style opens the intended Studio piece; no web reference becomes a cart item.

## MY CLOSET — remember and organize
Current: saved inspirations, looks, favorites, collections, cart/shortlist, private sync paths.
V1.2: make 'continue look', move to collection, resume shopping, and account/guest sync status discoverable. Never delete originals when deleting collection.
Acceptance: save a look, reload, open same item; rename/move a folder safely; verify isolated users with two real accounts.

## STUDIO — heart of the product
Current: focused photo/piece → preferences → results, nine-slot tree, budget and retailer alternatives.
V1.2: reduced step repetition, visible applied preference summary, safe temporary overrides, persistent context across STORE and CLOSET.
Acceptance: no added repetitive profile entry; preserve inspiration source; reject overbudget swap; maintain items through navigation.

## STORE — research and verified shopping
Current: verified Shopify and gated Awin searches, merchant/product page, opt-in web research.
V1.2: retain results and query when moving between tabs; honor MOOD category intent, provide explicit refresh for potentially stale listings; keep web sources separated from purchasable products.
Acceptance: MOOD → STORE fills term and category; STORE → another tab → STORE restores prior results with freshness warning, and fresh search revalidates; no web-research card can be added to cart.
Implementation: app-shell.js change on this branch.

## ME — preferences, identity and privacy
Current: dedicated Appearance / My style / My account / Privacy & data subpages.
V1.2: improve completion feedback, make saved-size versus temporary-override distinctions obvious, provide clear guest cloud-status and account data lifecycle.
Acceptance: profile edits affect new matching criteria without silently altering existing saved looks; appearance follows system and saved override; user A cannot read user B.

## Shared gates
- Exact deep forest green and GreenGlass in both themes.
- Keyboard focus, clear announcements for update/error states, 44px mobile targets where practical.
- No production deployment or paid API traffic without staging access and review.
- App audit and integration contract tests must run; mobile Safari + desktop walkthrough required.
- OpenAI discovery uses cited research, not training the model or pretending sources are in-stock.
- Keep Awin rows gated until qualified provider feed is inspected and allowed.
