# MATCHLATCH account onboarding — staging release gate

The login entry and signup modal are in V1.2 development only. Do not promote to staging or production until the checks below pass.

1. Apply reviewed SQL in `sql/matchlatch-private-profiles.sql` to the intended Supabase project; verify RLS with two independently authenticated test accounts and that each cannot read/update the other's profile. Until provisioning, UI warns that optional addresses were not saved.
2. Configure Supabase Auth signup confirmation email template to show `{{ .Token }}` rather than relying solely on a link. Confirm Supabase email confirmations are enabled, email provider and rate limits are appropriate, and `verifyOtp({email,token,type:"email"})` completes a real signup.
3. Test signup, email verification, password sign-in, sign-out, reload, wrong/expired code, blank fields, and account switching. Verify guest closet records remain distinct and no private data leaks between users.
4. Confirm password manager behavior, mobile layout, accessibility/keyboard interaction, optional fields, greeting, and that quiz answers influence styling context only after quiz submission.
5. No plaintext card number, CVV, expiry date, bank data, or biometrics are stored by MATCHLATCH. Payment methods including Apple Pay require a separate PCI-compliant processor integration and checkout merchant-of-record decision.
6. Passkeys/Face ID are experimental in current Supabase. Before enabling `MATCHLATCH_PASSKEYS_ENABLED=true`, enable Supabase Auth Passkeys in the dashboard; configure stable WebAuthn RP ID and allowed origins, review compatibility/version support, then test on Safari/iOS and on other platforms. Never label Face ID enabled merely because a device supports biometrics.
7. Do not create an administrator by editing user metadata or supplying a password in chat. Admin is a separate server-enforced capability with MFA, protected app metadata, and restricted RLS.
8. Run `node scripts/audit.mjs`, `node scripts/test-delivery-intelligence.mjs`, and `node scripts/test-public-catalog.mjs`. Verify GitHub Actions results and actual browser flows before stage promotion.

Known limitations: address persistence requires the private profile SQL deployment; the quiz presently affects the browser's local style research context, not a cross-device AI training or preference store; passkey controls are disabled by default; payments are not integrated.
